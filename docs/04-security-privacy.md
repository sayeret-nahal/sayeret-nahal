# אבטחת מידע ופרטיות

> המסמך מתאר את האמצעים הטכניים שמובנים במערכת. **הוא אינו חוות דעת משפטית.** הסעיפים שמסומנים ⚖ דורשים אישור של עורך/ת דין לפני שמעלים מידע אמיתי.

## 1. איזה מידע נשמר, ואיזה לא
- **נשמר:**
  - פרטי קשר
  - שיוך: מחזור גיוס ואזור מגורים
  - סוג הקשר עם העמותה
  - מצב קשר תפעולי (למשל "מעקב צמוד")
  - היסטוריית קשר: סיכומים קצרים
  - פניות
  - תרומות
  - כישורים
  - הסכמות
- **לא נשמר, בהגדרה:** אבחנות, תסמינים, תרופות, סיכומי טיפול או כל מידע רפואי או נפשי.
  - אין לזה שדות במסד הנתונים.
  - ליד כל שדה טקסט חופשי מופיעה אזהרה, והאורך שלו מוגבל.
- **[פרשנות] חלק מהמידע הוא כנראה "מידע בעל רגישות מיוחדת":**
  - מצב קשר ותגיות כמו "פצוע/ה", "בליווי מיוחד" ו"משפחה שכולה" עלולים להיחשב מידע כזה לפי תיקון 13.
  - לכן הם מוגנים בנפרד (סעיף 2). ⚖

## 2. מי רואה מה (נאכף במסד הנתונים, RLS)
- **ההרשאות נבדקות בתוך PostgreSQL, בכל שאילתה.** גם באג בממשק לא יחשוף מידע שהמשתמש לא מורשה לראות.
- **האפליקציה משתמשת רק במפתח הציבורי** ובסשן של המשתמש. אין בה "מפתח-על".
- **הטפסים הציבוריים** עובדים דרך פונקציות ייעודיות בלבד. למשתמש אנונימי אין גישה לטבלאות.

| תפקיד | אנשים | מצב קשר ופניות | תגיות רגישות | תרומות | יומן פעולות | ייצוא |
|---|---|---|---|---|---|---|
| מנהל/ת מערכת | כולם | ✓ | ✓ | ✓ | ✓ | ✓ |
| מנהל/ת עמותה | כולם | ✓ | ✓ | ✓ | — | ✓ |
| רכז/ת קהילה | כולם | ✓ | ✓ | — | — | — |
| אחראי/ת מחזור או אזור | בתחום שלו/ה בלבד | ✓ (בתחום) | ✓ | — | — | — |
| רכז/ת תורמים | תורמים בלבד | — | — | ✓ | — | — |
| מתנדב/ת | רק מי שהוקצה לו/ה | ✓ (רק תיעוד) | ✓ | — | — | — |

כל השורות בטבלה נבדקו בבדיקות אוטומטיות (`supabase/tests/db.test.ts`).

## 3. התאמה לתקנות אבטחת מידע (רמה בינונית)

| דרישה | איך מיושמת |
|---|---|
| הרשאות לפי הצורך וטבלת בעלי הרשאה עדכנית (תקנה 8) | הטבלה בסעיף 2 · ניהול ← משתמשים ← מטריצת הרשאות, עם ייצוא CSV |
| ביטול הרשאה מיד עם עזיבה | "השבתה" חוסמת את המשתמש מיידית בכל השאילתות |
| זיהוי חזק (תקנה 9) | סיסמה של 12 תווים לפחות + קוד מאפליקציית אימות (TOTP). בלי אימות דו-שלבי לא רואים אף נתון |
| ניתוק אחרי זמן ללא פעילות | אחרי 30 דקות (ניתן לשינוי), עם אזהרה דקה לפני |
| יומן גישה אוטומטי (תקנה 10) | `audit_log` מתעד: כל שינוי (מה היה לפני ומה אחרי), צפייה בכרטיס אדם או בפנייה, ייצוא, דוח, כניסה ויציאה. משתמשי האפליקציה לא יכולים לערוך או למחוק אותו. **צריך לשמור לפחות 24 חודשים** |
| הצפנה | בתעבורה: HTTPS, וגם HSTS. באחסון: הצפנת הדיסק של Supabase |
| גיבוי ושחזור | גיבוי יומי בתוכנית Pro, ומומלץ גם `pg_dump` שבועי מוצפן. בדיקת שחזור כל רבעון (`07-technical.md`) |
| אבטחת הדפים הציבוריים | הגבלת קצב: 3 לשעה לכל טלפון, 40 לשעה בסך הכול. מלכודת לבוטים. קישורי עדכון שמורים כ-hash בלבד, בתוקף 30 יום, וקישור חדש מבטל את הקודם |
| כותרות אבטחה | X-Frame-Options DENY, nosniff, Referrer-Policy, Permissions-Policy, HSTS |
| דוא"ל התראה | מכיל רק מספר פנייה ושם פרטי, בלי תוכן הפנייה, כי דוא"ל אינו ערוץ מאובטח |

## 4. הסכמות ויידוע
- **הודעת פרטיות (סעיף 11 לחוק)** מוצגת בכל טופס ציבורי. הגרסה שהאדם ראה, ותאריך הצפייה, נשמרים ברשומה שלו. ⚖ הנוסח הנוכחי הוא טיוטה.
- **הסכמה לפי מטרה:**
  - הודעות תפעוליות, כמו "אמת/י את הפרטים", אינן דורשות הסכמה.
  - פנייה לתרומה ב-SMS או בוואטסאפ דורשת הסכמה מראש (חוק התקשורת, סעיף 30א). השדה `campaign_consent` מוצג ליד כל תורם.
- **מאגר הכישורים:** אדם מוצג כמי שאפשר להפנות אליו אנשים רק אם סימן הסכמה לכך.

## 5. משימות לפני העלאת מידע אמיתי

| נושא | משימה |
|---|---|
| ⚖ הודעת פרטיות | אישור הנוסח |
| ⚖ מסמך הגדרות מאגר (תקנה 2) | אפשר להשתמש במסמכים 02, 03 ו-04 כבסיס |
| ⚖ ממונה הגנת פרטיות (DPO) | החלטה אם למנות |
| ⚖ הסכמי עיבוד נתונים | לחתום מול Supabase ומול ספק האירוח, ולתעד את מדינת האחסון (גרמניה) |
| נהל אבטחה כתוב | שנה מישהו אחראי, ותדריך לצוות |
| הגדרות מערכת | לוודא ש-`require_mfa = true` |
| נתוני דוגמה | למחוק אותם |
| בדיקת אבטחה | לבצע בדיקה מקצה לקצה מול הפרויקט האמיתי (`08-acceptance.md`) |
| גישה ל-Supabase עצמו | אימות דו-שלבי לכל מי שיש לו גישה לחשבון |

## 6. סקירת אבטחה בלתי תלויה (2 בנובמבר 2026)

סוכן נפרד בדק את הקוד ואת ההרשאות. הוא לא הסתפק בקריאה: הוא גם הריץ בדיקות חדירה למסד הנתונים. **לא נמצאו ממצאים קריטיים.**

התיקונים נמצאים במיגרציה `0005_hardening.sql`. לכל תיקון יש בדיקה אוטומטית ב-`supabase/tests/hardening.test.ts`.

| # | ממצא | מצב |
|---|---|---|
| H1 | דוחות ייבוא היו גלויים לכל תפקיד שמייבא, כולל רכז/ת תורמים: שם הקובץ, התגית הרגישה ומזהי האנשים | ✅ תוקן: גלויים רק למי שיצר אותם ולמנהלים |
| H2 | הגבלת קצב גלובלית אפשרה לכל אחד לחסום את "אני צריך/ה לדבר" לכל הקהילה | ✅ תוקן: עומס חריג רק **מסומן** "ייתכן שזו הצפה" ולא נחסם; לכל טופס מכסה נפרדת; נוספה הגבלה לפי כתובת IP |
| M1 | שדה "הערות כלליות" גלוי לרכז/ת התורמים | 🟡 צומצם: ליד השדה כתוב במפורש שהוא גלוי לרכז/ת התורמים, ושמידע על ליווי נרשם בתיעוד שיחה (שמוסתר מתפקיד זה). פיצול מלא של השדה הוא אפשרות לשלב 2 |
| M2 | אפשר היה לסמן אנשים אמיתיים "נתוני דוגמה" ולמחוק אותם, להעביר לארכיון דרך ה-API, ולהעביר רשומה אל מחוץ לתחום ההרשאה | ✅ תוקן: הרשאות ברמת עמודה, פונקציה למנהלים בלבד להעברה לארכיון, וטריגר שמונע יציאה מהתחום |
| M3 | אפשר היה לזייף מי יצר פנייה או משימה ולזייף את היסטוריית הפנייה | ✅ תוקן: "נוצר על ידי" נקבע אוטומטית ואי אפשר לשנות אותו; ליומן הפנייה אפשר להוסיף רק הערה או שיחה; "בוצע על ידי" נקבע אוטומטית |
| M4 | טופס אנונימי היה משייך פנייה לאדם לפי מספר הטלפון | ✅ תוקן: המערכת רק **מציעה** את האדם, והצוות מאשר את הקישור |
| M5 | הפניה אחרי כניסה לאתר חיצוני (open redirect) | ✅ תוקן |
| M6 | יומן הגישה לא כלל רשימות וחיפוש | ✅ תוקן: נרשמים גם רשימות, חיפוש ושיחות. 🟡 קריאות ישירות ל-API לא נרשמות. לרמה בינונית מומלץ להפעיל Log Drain ב-Supabase ולשמור את הלוגים 24 חודשים |
| M7 | ניתוק אחרי חוסר פעילות היה רק בצד הדפדפן | ✅ תוקן: נאכף גם בשרת (proxy). בנוסף כדאי להפעיל ב-Supabase את "Inactivity timeout" |
| L1 | פונקציות עזר פנימיות היו זמינות דרך ה-API (אפשר היה לגלות למי שייך מספר טלפון) | ✅ תוקן |
| L2 | אפשר היה לזייף רשומות "אימות דו-שלבי" ביומן או להציף אותו | ✅ תוקן |

| L4 | קישור עדכון עצמי היה שמיש 30 יום ללא הגבלה | ✅ עכשיו 14 יום ועד 3 שימושים. מתנדבים לא יכולים ליצור קישור |
| L5 | אפשר היה לגלות מי הוזמן דרך טופס ההרשמה | ✅ ההודעה זהה בכל מקרה. 🟡 מומלץ לסגור הרשמה פתוחה ולהזמין משתמשים דרך מסך Supabase |
| L6 | חסרה מדיניות CSP | ✅ נוספה. 🟡 עדיין מאפשרת סקריפטים מוטמעים (inline) בגלל Next.js. השלב הבא הוא nonce |
| L7 | רשומות חללים גלויות לכל התפקידים | ✅ עכשיו רק לתפקידים שעובדים עם משפחות |
| L8 | רכז/ת תורמים קיבל/ה מספרי פניות ושיחות בדוח | ✅ מקבל/ת רק מדדי תרומות |
| L9 | עריכת אירועים ומחיקת קמפיינים לא היו מוגבלות במסד הנתונים | ✅ תוקן |
| L10 | קובץ אקסל זדוני ("zip bomb") עלול לצרוך זיכרון בשרת | 🟡 פתוח: המגבלה היא 5MB לקובץ. מומלץ להגביל את הזיכרון גם בתשתית האירוח |

**מידע רגיש בטקסט חופשי:** סיכומי שיחה, תוכן פניות, הערות ומשימות עלולים להכיל מידע רגיש למרות האזהרות. יש לסווג אותם כרגישים במסמך הגדרות המאגר. ⚖
