## לוח זמנים: 4 שבועות עד שימוש מלא

### שבוע 1: הקמה (דורש החלטות מהעמותה)
- [ ] להקים פרויקט Supabase **בתוכנית Pro** בפרנקפורט, ולהריץ את המיגרציות (`supabase/migrations`).
- [ ] להעלות את האתר לאירוח, לחבר דומיין ולהגדיר משתני סביבה (`.env.example`).
- [ ] ליצור מנהל/ת מערכת ראשון/ה (ראו `07-technical.md`).
- [ ] **לאשר את ההנחות** בסעיף 7 של האפיון: שמות, תדירויות, תורן ל"אני צריך/ה לדבר" וזמן מענה.
- [ ] **ייעוץ משפטי:** נוסח הודעת הפרטיות, מסמך הגדרות המאגר, האם צריך DPO, והסכמי עיבוד נתונים עם Supabase ועם ספק האירוח.

### שבוע 2: נתונים
- [ ] למחוק את נתוני הדוגמה (ניהול ← נתוני דוגמה).
- [ ] להזין את רשימת המחזורים והאזורים (ניהול ← טבלאות עזר).
- [ ] לייבא את קובצי האקסל, **קובץ אחד בכל פעם**, ולבדוק את התצוגה המקדימה לפני השמירה.
- [ ] לעבור על עמוד "איכות נתונים" ולאחד כפילויות.
- [ ] לייבא קובץ תרומות ממערכת הסליקה.
- [ ] לשייך אחראי/ת קשר לכולם, למשל לפי מחזור, בעזרת עדכון קבוצתי.

### שבוע 3: פיילוט
- [ ] 2–3 משתמשים ו-2 מחזורים בלבד.
- [ ] בכל יום: "היום שלי", שיחות "מה נשמע", תיעוד.
- [ ] לשלוח קישורי עדכון פרטים לכל המחזור. זו גם בדיקה של כמה אנשים מגיבים.
- [ ] פגישת משוב של 30 דקות בסוף השבוע, ולתקן לפי המשוב.

### שבוע 4: פתיחה לכולם
- [ ] להזמין את כל המשתמשים. כל אחד עובר "כניסה ראשונה" לפי המדריך (5 דקות).
- [ ] לפרסם את הקישורים הציבוריים (ניהול ← קישורים ציבוריים): באתר העמותה, בתיאור קבוצות הוואטסאפ ובחתימת הדוא"ל.
- [ ] **מהיום, קבצי האקסל הישנים מוקפאים.** המערכת היא המקור היחיד.

## מדדי הצלחה (אחרי 90 יום)
- **אחראי/ת קשר:** ל-95% מהקהילה יש אחראי/ת.
- **פרטים מאומתים:** 60% אומתו ב-12 החודשים האחרונים. ביום ההשקה המספר קרוב ל-0.
- **פניות:** 0 פניות באיחור של יותר מ-7 ימים.
- **קשר עם מצבים דחופים:** כל מי שמסומן "במצוקה" או "מעקב צמוד" קיבל שיחה בתדירות שנקבעה.

## אחרי ההשקה (שלב 2, לפי סדר עדיפות)
1. **שליחת וואטסאפ אוטומטית** של בקשות לעדכון פרטים (WhatsApp Business API, כ-‎$0.005 להודעה תפעולית).
2. **חיבור אוטומטי למערכת הסליקה**, במקום ייבוא קובץ.
3. **מייל יומי מסכם** לכל משתמש: מה מחכה לו היום.
4. **פילוח אירועים והזמנות** לפי מחזור ומעקב אחר השתתפות.
